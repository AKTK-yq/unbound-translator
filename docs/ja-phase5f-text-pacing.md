# Phase 5F: Japanese text-progression investigation

## Symptom and method

Human mGBA check of the Phase 5E ROM found correct Japanese rendering and normal
Options operation, but a slight subjective difference in text progression. No
video/frame trace or matched Text Speed setting was supplied. This report is a
static PCS/Thumb-code analysis, **not** measured timing. The reproducible counts,
source strings, translations and exact byte streams are in
`out/ja-phase5f-pacing-analysis.json` (generated by
`scripts/audit_ja_phase5f_pacing.py`).

## Renderer and Text Speed path

The English Unbound ROM has `RenderText` at ROM `0x00005790`, GBA
`0x08005790`. At GBA `0x080057E6` it reads printer `delayCounter` (`r6+0x1E`),
at `0x080057EC` it reads `textSpeed` (`r6+0x1D`), and at
`0x080057F2–0x080057F4` it decrements the counter before returning. A/B
acceleration uses the path at `0x080057CC–0x0800581C`. At
`0x0800583C–0x08005846` the counter is reloaded and the next PCS byte read.
These checks precede the Japanese/Latin page distinction. A nonzero speed
therefore uses the same delay-counter path for either page; speed zero takes the
immediate path. The Options setting-to-printer-field caller has **not** been
traced, so the exact Options help behavior for each menu Text Speed value is
still a runtime question. Core-engine similarity to
[pret/pokefirered `src/text.c`](https://github.com/pret/pokefirered/blob/master/src/text.c)
is a secondary check; the addresses here come from this Unbound ROM.

Special bytes dispatch at `0x08005848–0x0800585A` through the jump table at
ROM `0x00005860`. `FE` is newline (`0x08005880`); `FA` scroll and `FB` clear
enter their respective page-state handlers at `0x08005B26` and `0x08005B22`.
`FC 15` and `FC 16` dispatch to `0x08005B10` and `0x08005B18`: they set or
clear the Japanese-page flag at printer `r6+0x21`, then return to the print
loop without an explicit timed wait. The ordinary glyph path starts at
`0x08005B6C` and normal-font glyph selection calls `0x080065B8` from
`0x08005BC0`. This path receives both Japanese and Latin glyph codes.

## Space and punctuation

PCS `00` is an ordinary glyph code, not a wait control. In the Japanese
normal-font branch, `0x080065C2–0x080065F2` checks code zero and fills a
blank glyph buffer with a 10-pixel advance; Latin space takes the branch at
`0x0800665C`. Thus space is blank, but still traverses the ordinary glyph
advance path and can consume one ordinary nonzero-speed delay opportunity.
The two pages have different spacing/width behavior, not a separate
delay-counter check. This is a code-path conclusion; actual on-screen frame
duration remains unmeasured.

Japanese `。` (`AD`), `！` (`AB`), `？` (`AC`) and ellipsis (`B0`) are ordinary
glyphs under the Japanese page. English period and the repo's `\.` spelling
also use glyph `B0` in their respective contexts. They do not by themselves
enter the `FC08` timed-pause or `FC09/0A` wait handlers. The literal `\+` is
glyph `2E`, not a timed pause. A translation can still have a separate `FA`,
`FB`, or explicit `[pause]`/wait token immediately nearby; that must be
checked at the byte level, not inferred from punctuation.

## Options examples: static glyph-advance steps

| Entry / ROM offset | English ordinary glyphs (spaces) | Japanese ordinary glyphs (spaces) | Explicit wait/page difference |
|---|---:|---:|---|
| Battle-difficulty help `tbl_menu_game_settings_00035_1F4E037` / `0x01F4E037` | 38 (5) | 22 (3) | none; Japanese adds only `FC15/16` page switches |
| Puzzle-difficulty help `tbl_menu_game_settings_00018_1F4DE12` / `0x01F4DE12` | 36 (4) | 22 (3) | none; Japanese adds only `FC15/16` |
| Text Speed label `tbl_menu_options_00001_419DD3` / `0x00419DD3` | 10 (1) | 7 (0) | none; Japanese adds only `FC15/16` |

For example, “The battle difficulty for all battles.” is translated as
`[japanese]すべての バトルに かかる むずかしさです。[latin]`. Its exact PCS is
`FC 15 0D 49 13 19 00 96 64 79 16 00 06 06 29 00 21 3E 06 0C 0B 44 0D AD FC 16 FF`.
The English bytes and the other samples are in the audit JSON. The counts are
static glyph-advance opportunities, **not** total frames. They exclude
dynamic buffer contents and menu redraw/cursor timing. The two Options help
translations have fewer glyphs and spaces than their English originals, so
extra Japanese spaces alone do **not** explain a slower Options observation.

Across all 674 Phase 5E translated entries, Japanese added `FC08/09/0A`
explicit wait controls to **0** entries. Relative to English, 112 entries
have more `FA`/`FB` page transitions (142 extra transitions). Compared with
the reviewed input immediately before controlfix, controlfix added 32 `FA`
and 28 `FB` across 8 entries as line/page layout; it added **zero** explicit
timed/press/sound waits. These 8 may merit future per-screen page QA, but the
sampled Options help lines are not among them. `FE` is a newline, not a
punctuation pause, and can still affect line layout.

## Diagnosis and next step

- **P1:** The space mechanism is proven; it is not supported as the cause of
  the sampled Options symptom (Japanese has fewer spaces/steps).
- **P2:** Explicit wait insertion is ruled out in the 674-entry static audit;
  controlfix page transitions elsewhere remain a possible separate layout
  issue.
- **P3/P4/P5/P6:** No Japanese-only core delay branch or punctuation-only
  wait found. Options-specific caller, menu redraw and dynamic-buffer runtime
  timing are not measured, so these cannot be fully excluded.
- **P7:** Best classification for the actual subjective Options symptom:
  **cause not yet identified**. Confidence in the code-path findings is high;
  confidence in a user-visible cause is low.

Capture short mGBA videos of the same Options help line in the unmodified and
Phase 5E ROMs, at identical Text Speed, with and without A/B held. Record the
first-glyph and last-glyph frame, cursor/menu redraw and any page transition.
Only then test the reversible, unapplied word-space A/B candidate in
`out/ja-phase5f-pacing-proposal.json`; it saves three static glyph steps but
may harm readability and is **not** a diagnosed fix. No renderer, ASM,
translation or controlfix change was made for pacing in Phase 5F.
